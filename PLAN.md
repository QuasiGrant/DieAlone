# Plan

How this file works:
- Cowork writes and orders the tasks. Code does them one at a time, top to bottom.
- Code may tick a box and add lines under Rules and Tips. Code does not add, remove, reorder, or reword tasks.
- A task is finished when its done-check passes, its box is ticked, and the work is committed and pushed.
- Only the current milestone is broken into tasks. Later milestones stay as headlines until they are next.

## Rules and Tips

Lessons from finished tasks that later tasks need. One line each, newest at the bottom.
- Editor eval (eval_file / unity command eval) wraps code in a method body: no `using` lines, use fully qualified names like UnityEditor.SceneManagement.EditorSceneManager. Screenshot save_path lands under Assets/, so save to the scratchpad copy and delete the Assets/Temp asset through the Editor afterward.
- Play mode does not tick while the Editor is unfocused. During bridge-driven play checks, eval `UnityEngine.Application.runInBackground = true` (runtime only, not saved) before waiting on frames.
- Deleting scripts through the Editor triggers a domain reload that drops the bridge mid-batch; wait for editor_status ready and retry the remaining calls. Build-list edits stay in memory until `UnityEditor.AssetDatabase.SaveAssets()` writes ProjectSettings/EditorBuildSettings.asset.
- Course geometry in Graybox: tunnel clearance 1.2 m, step 0.4 m, log 0.4 m, fence 1.5 m, ramp 14 degrees to a 1.5 m platform, stairs 0.25 rise 0.3 run, room doorway 1.0 x 2.1 m. For per-piece screenshots, render a temporary hidden camera to a RenderTexture from eval and write PNGs to the scratchpad; it leaves the scene clean.
- Tower layout: deck top at y 10, room interior 4 x 4 centered at (0, 10, 12), doorway in the south wall centered at x -1.1 (1.0 x 2.1 m), stair entry at ground on the north lane at x -1.5, z 8.4. Stacked stair flights must be slabs, not ground-to-top solids, or the upper flight swallows the lower one.
- Sprint speed is 5.5 m/s in code, owner raised it from the 4.5 in task 2.3 after testing. Cowork to record in DECISIONS.md.
- Player capsule: stand 1.8 m, crouch 1.0 m, radius 0.35, eye 1.6 / 0.8. Stand-up check is a SphereCast up from the crouched capsule top; to test it from eval, teleport the Player (disable the CharacterController around the position set, then Physics.SyncTransforms) and invoke HasHeadroom by reflection.
- STAIRS RULE: the Player CharacterController has stepOffset 0.1 and skinWidth 0.035, so it cannot climb steps. Every staircase gets a collider-only sloped box (a GameObject named StairRamp with just a BoxCollider) whose top face runs along the tread nosings, from one run below the first nosing to the top nosing. See Tower/Stairs/Flight1/StairRamp for the pattern. Reason: with stepOffset 0.3 the capsule slid up over any 0.35 to 0.65 m edge when moving sideways, so hop-only obstacles were climbable without jumping.
- Interaction: derive from Interactable (Assets/Scripts/Interaction), set the prompt string, override Use. PlayerInteractor on the Player raycasts 2 m from the camera and calls Use on the Interact action. HUD uses uGUI with legacy Text; TextMeshPro needs its Essential Resources imported first, which is an asset add. The center dot is HUD/Dot, active; the owner turned it off once and then asked for it back.
- Doors: Door component on a hinge object at the west jamb, Panel child cube 0.96 x 2.08 x 0.08 with the collider, kinematic Rigidbody on the hinge. Opens away from the user by the sign of dot(hinge.forward, toUser). Moving colliders that the player can touch should be driven this way, with an overlap check against the CharacterController before each step so they wait instead of pushing.
- Tunables: every feel number lives in Assets/Settings/PlayerTuning.asset (class PlayerTuning). New numbers for player, interaction, doors, and carrying go there as public fields with a Header, and scripts take a [SerializeField] PlayerTuning tuning reference wired in the scene. Capsule values are applied once in PlayerController.Awake.
- Carrying: Carryable on the object (needs a Collider and a Rigidbody), PlayerCarry on the Player with HoldPoint under the camera. Set down needs a surface with normal.y >= placeMinUpNormal within placeReach and a clear OverlapBox; otherwise E drops with physics and shows no prompt. Objects released before the follow lerp settles are released where they are. PlayerController.OnControllerColliderHit shoves non-kinematic bodies.
- Pause and settings: GamePause on the Game object owns timeScale, cursor, and which behaviours sleep while paused. PlayerSettings (Assets/Scripts/Settings) is a data class plus JSON save/load in persistentDataPath; add a field there and a control plus Bind method in PauseMenu. Menu rows live under PauseMenu/Panel/Content as a vertical stack. Input actions are added to InputSystem_Actions through the Editor API (asset.Disable, AddAction, AddBinding, write ToJson, ImportAsset, asset.Enable), never by hand. Throw is bound to right mouse and gamepad right trigger.
- Look camera spots for Milestone 3 screenshots, position then look-at point: A tower room (0.8, 11.6, 10.6) to (-1.0, 10.9, 13.4); B tower stairs (-2.6, 6.6, 7.7) to (2.0, 7.8, 8.4); C test course (-17, 1.6, 12) to (-17, 0.5, -20). Render them with a temporary camera copied from Camera.main (scratchpad shoot_look.cs pattern). Night is the scene default: Night/Moon directional light plus flat ambient, daytime "Directional Light" kept disabled. Materials are shared by texture and tiling under Assets/Materials; the tiling comes from each object scale, so resizing an object means reassigning its material.
- Look filter: LookFilterFeature (Assets/Scripts/Look) is a Render Graph ScriptableRendererFeature on Assets/Settings/PC_Renderer.asset, game camera only, BeforeRenderingPostProcessing. It blits camera color to a low-res texture and back through Assets/Shaders/LookFilter.shader pass 0. New effects: add a field to LookTuning, a property and a few lines to the shader, and set the property on the material in RecordRenderGraph. The shader must include URP Core.hlsl before Blit.hlsl or TEXTURE2D_X is undefined. Renderer features are added to the renderer asset through SerializedObject on m_RendererFeatures and m_RendererFeatureMap plus AddObjectToAsset (scratchpad wire_look.cs pattern). Shader compile check: UnityEditor.ShaderUtil.ShaderHasError.
- Look shader color math: the camera color is linear HDR at the filter point. Anything that judges darkness (black point, levels) must convert with LinearToSRGB, act, and convert back, or a small number looks huge. Saturation and chroma math are fine in linear.
- Look shader noise: use the PCG integer hash in LookFilter.shader for anything random per pixel; fractional hashes show a weave on whole-number inputs. Time comes in as _LookTime (unscaled) from the feature, so effects keep moving while paused. Fears to Fathom reference: grain subtle (about 0.15 to 0.25), bands rare or scripted.
- Scene-side look settings (fog, sky color) are applied every frame by LookEnvironment on the Game object from LookTuning. Add ambient or exposure there the same way rather than editing RenderSettings in the scene by hand.
- Final Milestone 3 look values live in Assets/Settings/LookTuning.asset; reference screenshots from the three spots are in Docs/Look (PNG, via LFS). Re-shoot with the shoot_look_final.cs pattern after any look change the owner signs off.
- Prefabs (Assets/Prefabs): Player, GameSystems (Game + EventSystem + HUD + PauseMenu), NightLighting (Moon + disabled Sun). Links that cross prefabs (GamePause behaviours, PlayerInteractor promptUI, LookEnvironment camera) resolve at startup by FindFirstObjectByType when left empty, so a new scene only needs the three prefabs dropped in. Graybox keeps explicit links as instance overrides. Never edit RenderSettings by hand: ambient is per scene, fog comes from LookTuning via LookEnvironment.
- NEW SCENE RECIPE: in Unity use the menu DieAlone > New Scene From Base, pick a name under Assets/Scenes, done. It instantiates Assets/Scenes/Templates/DieAloneBase.scenetemplate (built from Templates/Base.unity: Player, GameSystems, NightLighting prefabs, a 50 m dirt ground, night ambient, fog) and adds the scene to the build list. From code call NewSceneMenu.CreateScene(path) (Assets/Editor/NewSceneMenu.cs). To change what every new scene starts with, edit Base.unity and re-run the template creation; the template references assets, it never clones them.
- InputSystemUIInputModule in a prefab must have its action fields (point, leftClick, submit, cancel...) set to the InputActionReference sub-assets of InputSystem_Actions.inputactions (LoadAllAssetRepresentationsAtPath, names like "UI/Point"). Assigning only actionsAsset creates scene-local references that a prefab drops, and menus stop taking clicks in new scenes. To test a UI click from eval, add a virtual Mouse device and spread move, press, release over separate frames.
- Dev-only code: wrap the whole class body in #if UNITY_EDITOR || DEVELOPMENT_BUILD and build any UI from code inside it, so release builds get an empty component and no assets. Prove it by building to Build/Release (git-ignored) and loading Build/Release/DieAlone_Data/Managed/Assembly-CSharp.dll with System.Reflection.Assembly.LoadFile from eval, then listing the type members. Mono.Cecil is ambiguous in eval (Burst ships its own copy). A player build rewrites several Settings assets with build-time values; commit those on their own.
